Security & Identity Specification

Placement AI (PAI) Authentication Module Architecture

Technical guide: Supabase GoTrue IdP, JWT local validation, Person bootstrap, session cookies, and security gates

1. Core Architectural Principles

Key Security & Design Invariants:
  • Decoupled Identity vs Profile: Credentials and passwords reside in Supabase GoTrue. PAI's internal database stores the canonical Person and PersonVault, lazily provisioned on verified authentication.
  • Local Stateless JWT Verification: Incoming Bearer tokens are cryptographically checked locally in-memory (symmetric HS256 secret or asymmetric ES256/RS256 via 600s cached JWKS).
  • Double-Submit CSRF + HttpOnly Refresh Tokens: Access tokens are returned in JSON; refresh tokens reside in HttpOnly, SameSite=Lax cookies. Sensitive state changes require an matching X-CSRF-Token header.
  • Onboarding Gatekeeper: Authenticated tokens cannot access counseling or document APIs until the student's initial onboarding is marked complete.

B. Authenticated Request Guard Pipeline

HTTP Request: `Authorization: Bearer ` │ ├── 1. Bearer Scheme Check: Strips whitespace, rejects non-Bearer or malformed prefixes. │ ├── 2. JWT Verification (validate_access_token): │ • Algorithm detection (HS256 vs ES256/RS256). │ • Signature validation against local secret or cached JWKS (TTL: 600s). │ • Audience validation: `aud == 'authenticated'`. Expiration: `exp > now`. │ ├── 3. Distributed Rate Limiter: │ • Consumes 1 token from user request bucket (e.g. 60 requests/min). │ ├── 4. Person Resolution: │ • Queries `persons` table where `external_auth_id == sub`. │ └── 5. Onboarding Verification: • Enforces `person.onboarding_completed_at is not None`. • If None, returns 403 ONBOARDING_INCOMPLETE.

3. Comprehensive Code & Directory Index

Layer 1: Interfaces & Security Dependencies

File Path Component Responsibilities & Key Handlers
src/pai/interfaces/api/auth.py Defines FastAPI authentication and account management endpoints:
  • signup(): Registers user, checks existing identities.
  • login(): Issues session bundle and sets session cookies.
  • refresh_tokens(): Rotates tokens using HttpOnly cookie; guarded by CSRF.
  • logout(): Revokes session on Supabase and clears cookies.
  • confirm_email_verification(): Confirms 6-digit OTP code.
  • change_password() / reset_password(): Password lifecycle.
  • me(): Returns current user identity and onboarding status.
  • delete_account(): Anonymizes local student records and deletes identity from GoTrue.
src/pai/interfaces/api/dependencies.py Security dependency injection guards:
  • get_current_access_token(): Extracts Bearer token.
  • get_validated_access_token(): Cryptographically validates token and checks rate limits.
  • resolve_person_from_token(): Maps JWT sub to local Person model.
  • require_onboarding_complete(): Enforces onboarding completion.
  • require_csrf(): Validates Double-Submit CSRF cookie pattern against header.

Layer 2: Platform Security & Identity Providers

File Path Component Responsibilities
src/pai/platform/security/auth/provider.py Defines the AuthProvider abstract protocol and data models (ProviderUser, ProviderSession, SignupResult).
src/pai/platform/security/auth/supabase.py Implements AuthProvider via Supabase GoTrue REST API. Contains custom IPv4 transport binding (bypassing Windows IPv6 resolution latency) and error translation mapping.
src/pai/platform/security/auth/jwt.py Stateless JWT validator. Manages JWKS cache with thread-safe locking, handles HS256/ES256/RS256 algorithms, and validates audience/subject claims.
src/pai/platform/security/auth/service.py AuthService domain orchestrator. Manages SessionBundle generation (access token, refresh token, CSRF secret creation).
src/pai/platform/security/sensitive_values.py SensitiveValueCodec: Fernet symmetric encryption engine protecting sensitive fields at rest using VAULT_ENCRYPTION_KEY.

Layer 3: Student Domain & Person Provisioning

File Path Component Responsibilities
src/pai/domains/student/person/models.py Defines the student database entities:
  • Person: Local identity record (external_auth_id, email, onboarding_completed_at).
  • PersonVault: Root vault entity storing catalog schema and completion metrics.
src/pai/domains/student/person/service.py PersonBootstrapService: Executes atomic row-locking provisioning (_get_person_for_update) to link the Supabase user to a local Person and initialize their PersonVault upon verification.

4. Session, Cookie & Security Configuration

Configuration Key Default / Recommended Security Purpose
COOKIE_SECURE false (dev) / true (prod) Enforces HTTPS-only transmission for session cookies.
COOKIE_SAME_SITE lax Defends against Cross-Site Request Forgery (CSRF).
REFRESH_COOKIE_NAME pai_refresh_token HttpOnly cookie storing the long-lived refresh token.
CSRF_COOKIE_NAME pai_csrf_token Readable cookie for client double-submit token verification.
SUPABASE_JWT_AUDIENCE authenticated Audience claim verified against incoming JWTs.
AUTH_HTTP_TIMEOUT_SECONDS 10.0 Network timeout for outbound calls to Supabase GoTrue.
