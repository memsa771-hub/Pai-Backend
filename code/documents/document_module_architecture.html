Internal Engineering Specification

Placement AI (PAI) Document Module Architecture

Complete technical guide: Directory breakdown, data models, worker pipeline, and Vault reconciliation

1. Core Architectural Philosophy

The Fundamental Constitution:
  • AI Never Writes Truth Directly: Models and OCR engines are only permitted to propose interpretations into a quarantined staging table (document_candidates with review_status = 'pending').
  • Human-in-the-Loop Gate: Extracted facts are only promoted to the canonical Student Vault (vault_values) when the student confirms them via POST /api/v1/documents/{id}/review.
  • Evidence-Backed Profile: Every fact in the Vault links to immutable source records in vault_evidence (document ID, snippet, and confidence).
  • Strict Tenant Isolation: Storage paths, database queries, and background advisory locks strictly scope to the student’s authenticated person_id.

2. End-to-End Processing Flow

3. Detailed Directory & Code Map

Every file responsible for document functionality is organized into three architectural layers:

Layer 1: Interfaces & Workers (Network Entrypoints)

File Path Component Responsibilities & Handlers
src/pai/interfaces/api/documents.py Exposes the FastAPI document endpoints. Validates onboarding state, handles multipart uploads, streams signed URLs, and processes candidate accept/reject reviews.
src/pai/interfaces/workers/documents.py CLI process entrypoint (py run.py --service documents). Runs the asynchronous loop polling for pending jobs.

Layer 2: Domain Layer (Models, Storage & Business Logic)

File Path Component Responsibilities & Handlers
src/pai/domains/documents/models.py Defines SQLAlchemy database entities:
  • Document: Main metadata record (lifecycle, category, status).
  • DocumentVersion: Revision tracking, SHA256 checksums, extracted text.
  • DocumentJob: Worker queue tracking lease, stage, attempts, errors.
  • DocumentCandidate: The Staging Area holding pending AI proposals.
  • DocumentAnalysisRun: Run-level audit record.
  • MessageDocument: Attachment mapping to chat messages.
src/pai/domains/documents/service.py Contains domain operations: review_document_candidates(), list_documents(), get_document_owned(), and mark_document_deleted().
src/pai/domains/documents/text.py Low-level text extraction from binary buffers using pypdf.
src/pai/platform/storage/supabase.py Manages raw object storage in Supabase private buckets (upload_private, download_bytes, create_signed_download_url, delete_object).
src/pai/kernel/evidence/vault_apply.py The deterministic gate that writes approved candidates to vault_values, links evidence to vault_evidence, and logs to vault_history.

Layer 3: Intelligences Layer (The Processing Pipeline)

Folder / File Functionality
intelligences/documents/ingest.py Immediate upload orchestrator: validates bytes, uploads to Supabase, creates DB entities.
intelligences/documents/pipeline.py The master analysis pipeline: coordinates digitization, classification, extraction, identity checks, and candidate generation.
digitization/service.py Routes files between native text parsers and AI vision OCR.
providers/native.py Zero-latency extraction for digital PDFs, DOCX, and text.
providers/openai_vision.py Multimodal OCR engine using gpt-4o-mini for scans, photos, and handwritten documents.
classification/classifier.py Classifies document category and specific type (e.g. transcript, test_score, passport).
extraction/extractor.py Prompts LLM with structured Pydantic schemas to output strictly typed JSON facts.
extraction/schemas/ Structured Pydantic definitions: transcript.py, degree.py, passport.py, test_score.py, resume.py.
identity/matcher.py Validates that the document subject name/DOB matches the student account.
normalization/ Normalizes variations into global standards: gpa.py, dates.py, institutions.py, names.py.
reconciliation/engine.py Compares extracted candidates with existing profile data; creates proposals and flags conflicts.
verification/service.py Opens, resolves, and tracks verification_cases.
workers/analysis_worker.py Background daemon polling loop, lease management, and advisory locks.

4. Database Schema Reference

Table Name Key Columns Purpose & State
documents id, person_id, document_type, category, status, storage_path Master record. Status moves: uploaded ➔ digitizing ➔ classifying ➔ extracting ➔ reconciling ➔ ready / awaiting_review ➔ processed.
document_versions id, document_id, version_number, sha256, content_text Tracks revisions, file hash, digitized raw text, and encrypted JSON extraction.
document_jobs id, document_id, status, attempts, current_stage, locked_at Worker queue. Status: pending ➔ processing ➔ completed (or failed after 3 attempts).
document_candidates id, document_id, field_key, value, confidence, review_status The Staging Area: AI-extracted proposals awaiting human approval (pending, accepted, or rejected).
vault_values id, vault_id, field_key, value, status, verification_level The Official Student Vault: Active student profile truth (status = 'active').
vault_evidence id, vault_value_id, source_reference, evidence_text, confidence Auditable link connecting a Vault fact back to the document ID and exact text snippet.
verification_cases id, person_id, document_id, case_type, severity, status Logged when identity mismatches or critical grade discrepancies are found.

5. Swagger API Quick Reference

Method Endpoint Summary
POST /api/v1/documents Upload document (returns 202 Accepted immediately).
GET /api/v1/documents List all documents for the authenticated student.
GET /api/v1/documents/{id}/status Poll worker processing stage and job status.
GET /api/v1/documents/{id}/candidates Inspect AI-extracted proposals waiting in the staging area.
POST /api/v1/documents/{id}/review Accept or reject candidate proposals into the Student Vault.
GET /api/v1/documents/{id} Get metadata, decrypted extraction, and signed download URL.
DELETE /api/v1/documents/{id} Delete document from database and purge from Supabase storage.
